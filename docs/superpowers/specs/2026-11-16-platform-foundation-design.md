# 小學教學平台：第一階段「平台地基」設計

日期：2026-11-16
狀態：待核准

## 1. 目的

現有專案是一個給一年級學生用的原型「小一上數學互動教室」，全部內容放在單一 `index.html`。目標是把它擴成公開的小學教學平台，涵蓋小一到小六的數學、英文與自然科學，部署在 GitHub Pages 讓任何人免費使用。

整個平台的內容量約是現在的 30 倍（數學 12 個學期，英文與自然各約 8 個學期，目前只有 1 個學期）。這個量無法一次做完，所以拆成數個階段：

| 階段 | 內容 | 本文件是否涵蓋 |
|---|---|---|
| 1. 平台地基 | 新架構、搬移現有 12 個單元、部署上線 | 是 |
| 2. 數學擴充 | 一下起，逐學期新增 | 否，另行設計 |
| 3. 英文 | 起始年級與內容另行設計 | 否 |
| 4. 自然科學 | 起始年級與內容另行設計 | 否 |

本文件只設計第一階段。第一階段完成時，網站的教學內容與現在相同，但之後新增任何年級、科目的單元都不必再改動平台本身。

## 2. 目標、非目標與失敗條件

### 目標

1. 現有 12 個單元與 2 個總複習在新架構下行為不變，包含動畫、語音、練習題與「錯的再練一次」。
2. 新增一個單元只需要新增檔案並在目錄登記，不需要修改平台程式。
3. 單元可以用「範本」寫成，也可以掛上手寫的專屬場景，兩種寫法能在同一個單元裡混用。
4. 網站公開部署在 GitHub Pages，推送到主分支後自動更新。
5. 同一個瀏覽器可以切換多個孩子，進度可以匯出成檔案，再匯入到另一台裝置。
6. 網站可以「安裝」到平板或電腦，安裝並下載教材後，沒有網路也能使用（見第 6 節）。

### 非目標

- 不新增教學內容。唯一的例外是一個用來驗證範本與英文語音的示範單元（見 5.4）。
- 不做帳號、登入與任何伺服器端功能。
- 不做教師後台、班級管理與學習報表。
- 不蒐集任何使用者資料，不放流量分析工具。

### 失敗條件

以下任一項發生，即使功能都做完也算失敗：

- 搬移後的單元比現在陽春，例如曲線拉直、火車排序這類互動消失或變成靜態圖。
- 新增單元時仍然要改到共用的平台程式。
- 網站上出現出版社課本的題目、圖片或文字。
- 公開的原始碼或網站上留有孩子的個人資訊。

## 3. 限制

- **只能是靜態網站。** GitHub Pages 只提供檔案，不能執行伺服器程式，所以進度只能存在使用者的瀏覽器裡。
- **原始碼公開。** GitHub 免費方案的 Pages 需要公開的儲存庫。
- **教材不能來自課本。** 單元以教育部 108 課綱的學習內容條目為依據來編排，題目與圖全部自製。出版社只出現在「版本對照表」，用來告訴家長某個單元對應課本的哪一章。
- **使用者是小學生。** 低年級不識字或識字不多，操作必須靠語音、圖像與大按鈕；主要裝置是平板與電腦。

## 4. 做法比較

| 做法 | 說明 | 取捨 |
|---|---|---|
| A. 每個單元各自手寫 | 把 `index.html` 拆檔，共用繪圖工具，每個單元仍是手寫程式 | 精緻度最高，但 30 倍的內容全靠手寫，進度太慢 |
| B. 全部用範本 | 做一組通用互動元件，單元只寫資料檔 | 新增單元最快，但現有的客製動畫放不進範本 |
| **C. 範本為主，保留客製出口** | 預設用範本，個別單元可以掛手寫場景 | 現有成果不必重做，新內容也鋪得快；代價是要定義兩者共存的規則 |

使用者選擇 **C**。

## 5. 設計

### 5.1 現有程式的結構

現有 `index.html` 已經把「引擎」和「單元」分得相當清楚，這是選 C 的基礎：

- **單元**是一個物件，欄位有 `key`、`icon`、`name`、`desc`、`scenes`、`practice`、`count`、`tip`、`task`。
- **場景**（`scenes` 的每一項）是 `{ title, async run(id) }`，`run` 直接在 SVG 畫布上畫圖、播語音、等使用者操作。
- **練習題型**是一個函式，每次呼叫產生一題隨機題目，回傳 `{ mode, prompt, answer, draw(), explain(id) }`。`mode` 目前有 `pick`、`num`、`pair`、`dual` 等幾種作答方式。
- **引擎**負責場景切換（上一步、重播、下一步）、練習流程、計分、語音與星星存檔。
- 繪圖輔助函式依主題用前綴分組：`a_`、`b_`、`c_`、`d_`。

新架構沿用這份「單元合約」，只是把它從一個檔案拆到多個檔案，並補上平台需要的欄位。

### 5.2 檔案結構

以下是建議的分層，檔名與細部切法由實作者決定：

```
src/
  engine/     場景播放、練習流程、語音、SVG 基本工具
  templates/  通用範本（場景範本與題型範本）
  platform/   首頁導覽、路由、進度與孩子切換、匯出匯入
  content/
    catalog   全站目錄：有哪些年級、科目、單元
    math/g1a/ 一上數學的 12 個單元，各自一個檔案
    english/  示範單元
docs/
  curriculum/ 課綱文件（現有的 `小一上數學課綱.md` 移到這裡）
```

每個單元檔案只在使用者打開該單元時才下載。首頁只需要目錄裡的名稱、圖示與說明。

### 5.3 單元合約

單元沿用現有欄位，並新增以下資訊：

| 欄位 | 用途 |
|---|---|
| 科目、年級、學期 | 首頁分類與網址 |
| 課綱條目代碼（例如 `N-1-1`） | 對照課綱；之後可依條目搜尋 |
| 版本對照 | 這個單元對應翰林、康軒、南一的哪一章 |
| 語言 | 語音預設用中文或英文 |
| 固定 ID（例如 `G1-N-03`） | 進度存檔的鍵值。訂下後永不更改，不直接用課綱代碼，因為課綱代碼可能改版 |
| 先修單元 `prereqs`（選填） | 之後做「卡住時推薦前一個單元」用，第一階段只保留欄位 |

題型產生的題目，也預留三個選填欄位，第一階段只定格式、不改變現有單元的行為：

| 欄位 | 用途 |
|---|---|
| `hints` | 作答中的分層提示 |
| `boost` | 再答錯時，把題目拆成小步驟的補救互動 |
| `rationale` | 作答後的正解說明（現有的 `explain` 就屬於這一類） |

研究顯示「提示 → 補救 → 正解」是學習平台最有效的答錯處理方式。這些欄位越晚加，要回頭修改的題型越多，所以在地基階段先定下來（設計者決定）。

場景與題型各有兩種寫法，可以在同一個單元裡混用：

- **手寫**：和現在一樣，是一個直接操作畫布的函式。現有 12 個單元全部屬於這一類。
- **範本**：寫成一份資料，指定用哪個範本與內容。引擎把它轉成和手寫場景相同的形式再執行。

因為兩種寫法最後都變成同一種形式，引擎不需要知道某個場景原本是哪一種。

### 5.4 第一階段提供的範本

第一階段只做足以驗證機制的最小範本組，更多範本留到各科擴充時依實際需要再加：

- **選擇題**：題目與選項可以是文字、表情符號或圖片。
- **聽音選擇**：播放一段語音，從選項中選出對應的答案。
- **配對**：把左右兩組項目連起來。
- **講解場景**：依序顯示圖文並播放語音，可以穿插「按一下繼續」。

另外做一個英文示範單元（例如字母或基本單字），全部用範本寫成。它的用途是證明兩件事：不寫繪圖程式也能做出一個完整單元，以及英文語音可以正常運作。示範單元在首頁標示為「試玩」。

### 5.5 導覽與網址

首頁有兩個入口（依研究結果，設計者決定）：

- **主入口：一顆大大的「繼續學習」按鈕。** 直接打開建議的下一個單元：上次做到哪裡，或哪個單元還沒滿星。小一、小二不需要讀字就能使用。這是 Khan Academy Kids 與 Zearn 的做法。
- **次入口：「自己選」。** 流程是選年級 → 選科目 → 看到單元清單 → 進入單元，給大孩子和家長使用。

```
        [ ▶ 繼續學習：〰️ 曲線比長短 ]          ← 最大的按鈕

自己選：
[ 一年級 ] [ 二年級 ] [ 三年級 ] ...        ← 沒有內容的年級顯示「準備中」

一年級
  [ 🔢 數學 ]  [ 🔤 英文（試玩） ]  [ 🔬 自然 準備中 ]

一年級 數學 上學期
  一、10 以內的數     🔢 10以內的數 ⭐⭐☆
  二、比長短          📏 直線和曲線 ⭐⭐⭐  〰️ 曲線比長短 ☆☆☆ ...
  🏆 總複習
```

每個年級、科目與單元都有自己的網址，可以直接分享或加入書籤。網址採用 `#` 開頭的路徑形式（例如 `#/g1/math/a/num10`），因為 GitHub Pages 不支援把任意路徑導回首頁，用 `#` 可以避開這個限制。

現有的「給爸媽」說明區保留，內容改為依目前所在的年級與科目顯示。

課綱代碼只出現在資料與「給爸媽」區，不顯示在孩子的畫面上。研究發現因材網把課綱代碼直接給學生看，對兒童不友善。

### 5.6 進度與多個孩子

- 進度存在瀏覽器的 `localStorage`，資料格式帶版本號，方便日後調整。
- 可以建立多個孩子的檔案（只有暱稱與圖示），在首頁切換。第一次進站時不強迫建立，直接使用預設檔案。
- 提供「匯出進度」下載成一個檔案，以及「匯入進度」讀回檔案。這是在沒有帳號的前提下，換裝置時保留進度的方法。
- 不搬移舊版的星星紀錄（設計者決定）。舊版從本機檔案開啟，新版在 GitHub Pages 網址上，瀏覽器把兩者的儲存空間分開存放，新版讀不到舊資料。舊版只在少數裝置上使用過，重新累積星星的代價很小，不值得為此多做一條匯出路徑。

### 5.7 語音

沿用瀏覽器內建的語音朗讀。`say` 增加語言參數，可以在同一個場景裡混用中文與英文（英文單元常見「中文說明＋英文單字」）。瀏覽器沒有對應語言的語音時，照現在的做法只顯示字幕並等待相當的時間。

英文發音若在實際使用後發現品質不足，再評估改用預錄音檔。這不在第一階段範圍內，但語音介面的設計不應該排除這個可能。

其他規則：

- **保留「打開喇叭」開場畫面。** 瀏覽器不允許網頁在使用者點擊之前自己發出聲音。現有程式已經用這個畫面解鎖語音，新架構要保留，範本也要固定放一個「🔊 再聽一次」按鈕。
- **音效與朗讀分開開關。** 第一階段會加入答對、答錯、得星星的音效（見 5.12）。家長常抱怨音效太吵，所以音效要能單獨關掉，而朗讀照常播放。

### 5.8 建置與部署

- 使用 Vite 作為建置工具，維持原生 JavaScript，不引入前端框架。現有程式全部是原生 JavaScript 加 SVG，這樣搬移成本最低。
- 用 GitHub Actions 在推送到主分支時自動建置並發佈到 GitHub Pages。
- 儲存庫名稱會成為網址的一部分，建置設定要能配合調整。

### 5.9 上線前要清除的個人資訊

- 單元卡片上個人化的弱點標籤與對應的 `weak` 欄位。
- 課綱文件中的個人弱點註記。
- 「給爸媽」區塊裡針對特定考卷的提醒，改寫成一般性的建議。
- 首頁說明文字「依翰林版一上課本順序排列」，改成以課綱主題描述，並指向版本對照表。

章節名稱（例如「一、10 以內的數」）是通用的主題名稱，可以保留。

**版本歷史也要乾淨（設計者決定）。** 專案目前還不是 Git 儲存庫。上述清除工作完成後才做第一次提交，確保公開的歷史紀錄裡從來沒有出現過這些內容。這份設計文件本身也會在提交前改寫成不含個人資訊的版本。

**版本對照（設計者決定）。** 對照欄位允許留空。第一階段只確實填寫翰林的章名；現有的康軒／南一合併對照表標示「僅供參考」，三家逐一查證留到後續階段。

### 5.10 驗證方式

現有程式留有測試用的 `window.__T`，可以用程式模擬作答。新架構保留這個入口，並以它為基礎做自動檢查：

- 每個單元的每個場景都能從頭播到尾，過程中沒有錯誤。
- 每個練習題型都能產生題目，答對與答錯兩條路都能走完。
- 舊的星星紀錄能正確轉入新格式；匯出後再匯入，進度完全相同。

搬移的完成條件是：12 個單元與 2 個總複習逐一和現有 `index.html` 對照，互動與講解內容沒有差異。

### 5.11 考卷驅動的內容更新流程

使用者會持續提供學生的考卷，用來更新題目。考卷大多是出版社或測驗卷廠商的著作，而網站是公開的，所以考卷不能原樣上網。流程如下：

1. **考卷只當「題型參考」。** 從考卷整理出題型、陷阱與孩子容易錯的地方，例如「短針在 3 和 4 中間，誤讀成 4 點半」。
2. **題目全部自製。** 依題型寫成會隨機產生的題型函式，數字、情境與圖都重新設計，不照抄考卷的文字或圖。現有的「考卷變形題」就是這種做法。
3. **考卷檔案不進儲存庫。** 考卷照片或掃描檔放在儲存庫以外的資料夾，或列入 `.gitignore`。考卷上通常有孩子的姓名、班級與分數，不能出現在公開的歷史紀錄裡。
4. **介面不提「考卷」。** 例如「考卷會這樣考」改成「容易搞錯的題目」，「10 題考卷變形題」改成「10 題挑戰題」。

### 5.12 美術與介面套件

使用者要求美術與介面使用開源套件。選型依據是 2026-11-16 的研究（`docs/research/2026-11-16-platform-and-ui-kit-research.md`），每一項的授權都由第二位研究者打開官方授權頁獨立核對過。以下組合由設計者依研究推薦決定：

| 類別 | 選用 | 授權 | 用途與注意事項 |
|---|---|---|---|
| 設計變數（尺寸、圓角、陰影、動畫） | Open Props | MIT | 只提供變數、不帶外觀，最容易延續現有的奶油色與大圓角風格。固定版本，只引入需要的部分 |
| 元件 | 自己寫一層小型 CSS | 自有 | 需要的元件很少：大按鈕、單元卡、星星、進度條。對話框用瀏覽器原生的 `<dialog>` |
| 題目與物件插圖 | Microsoft Fluent Emoji（Flat／Color SVG） | MIT | 範本單元的圖卡、數數物件、英文單字圖。直接把 SVG 複製進專案，不用 3D 的大 PNG |
| 介面圖示 | Tabler Icons | MIT | 有實心版本，持續維護中。給小孩用要加粗、放大 |
| 音效 | Kenney（UI Audio、Interface Sounds 等） | CC0 | 答對、答錯、點擊、得星星 |
| 中文字型 | jf open 粉圓（Huninn，透過 Google Fonts） | OFL-1.1 | 台灣圓體，適合兒童。用 Google Fonts 版，不自行裁切字型；自行裁切等於修改，依授權必須改名 |

範圍限制：

- **現有單元的手繪 SVG 場景不換成套件素材。** 曲線、書本、火車這類圖是教學內容的一部分，第一階段要求行為不變。套件素材用在首頁、介面元件與新的範本單元。
- **Noto Sans TC 保留為備用字型。** 它在研究清單裡，但這次的授權核對沒有涵蓋，實作時再補核一次。
- **離線時的字型。** Google Fonts 會由離線快取一併存下；取不到時退回系統字型，版面不能因此跑掉。

不採用的選項與原因：

- **daisyUI + Tailwind CSS**：主題漂亮，但等於整個專案改用 Tailwind 寫樣式，代價太大。
- **Web Awesome**：品質好，但免費與付費元件混在一起，而且我們需要的元件很少。之後真的需要複雜元件時再考慮。
- **Pico CSS、Shoelace**：已經停止維護。
- **unDraw**：授權禁止打包轉發，放進公開儲存庫有疑慮。
- **LottieFiles 動畫**：動畫的授權不是開源授權。慶祝動畫改用 CSS 與 SVG 自己做。
- **任何 NC（禁止商用）或 ND（禁止改作）授權的素材**：不相容。

### 5.13 授權管理

- 程式碼用 MIT 授權。素材各自保留原授權，不歸在 MIT 底下。
- 儲存庫建立一份素材授權清單，記錄每個素材的來源網址、授權與作者。網站加一個「致謝」頁，由這份清單產生。
- 研究過的平台（Khan、Duolingo、PhET 等）只借互動模式，不借美術、角色、截圖與題目文字。
- PhET 的原始碼是 GPLv3（要求衍生程式也用相同授權），不能複製進本專案。

## 6. 和現在不同的地方：連網與離線

**主要用法改成開網址。** 拆成多個檔案後，瀏覽器基於安全限制不允許直接從本機檔案載入其他模組，所以「雙擊 `index.html`」的用法會取消。`README.md` 的使用說明要跟著改寫。

**離線用法改成「安裝」網站（設計者決定）。** 做法是 PWA（Progressive Web App，可安裝的網頁應用程式），也就是讓網站可以像 App 一樣加到平板主畫面，並把教材存在裝置上：

- 進過的單元會自動存起來，之後沒網路也能開。
- 首頁提供「下載全部教材，離線使用」的按鈕，可以依年級與科目選擇要下載哪些。
- 網站更新時，裝置在下次連網時自動取得新版。
- 語音使用的是裝置內建的朗讀功能，離線時仍可使用。網路字型在離線時改用系統字型。

另一種做法是額外產生一個打包成單一檔案的離線版，讓使用者下載後雙擊開啟。不採用的原因是：教材越多檔案越大，而且要維護兩種版本。

## 7. 決策紀錄

**使用者決定的**

- 平台涵蓋小一到小六的數學、英文、自然科學。
- 部署在 GitHub Pages，公開給所有人使用。
- 架構採用做法 C。
- 題目會依使用者持續提供的考卷更新。
- 主要用法是連網開啟；下載後也要能離線使用。
- 美術與介面使用開源 UI／UX 套件（選型依研究結果另行補充）。

**設計者提出、尚待使用者確認的**

- 考卷只當題型參考，題目全部自製，考卷檔案不進儲存庫（5.11）。
- 用 PWA 做離線，不另外產生單一檔案的離線版（第 6 節）。
- 美術與介面套件組合：Open Props、自寫 CSS、Fluent Emoji、Tabler Icons、Kenney 音效、粉圓字型（5.12）。
- 首頁加「繼續學習」主入口（5.5）。
- 單元與題目預留固定 ID、先修單元、分層提示、補救、正解說明欄位（5.3）。
- 音效與朗讀分開開關（5.7）。

- 把工作拆成四個階段，第一階段只做地基。
- 以課綱條目編排單元，出版社只做對照表。
- Vite、原生 JavaScript、不用框架。
- `#` 形式的網址。
- 多個孩子的檔案與進度匯出、匯入。
- 最小範本組的四個範本，以及一個英文示範單元。

**留給實作者決定的**

- 檔案與模組的細部切法、命名。
- 範本資料的確切欄位格式。
- 進度資料的確切結構。
- 自動檢查使用的測試工具。
- 首頁的視覺細節，但要延續現有的配色與大按鈕風格。

**研究建議、但留到第二階段以後的**

這些都來自研究報告第 8.2 節，第一階段的地基已經為它們留好欄位或空間：

- 答錯三段處理（提示 → 補救 → 正解）實際套用到各單元。
- 家長專區：家長閘門（用國字出算數題）、錯題紀錄、「需要陪他看」提示、解鎖或跳過單元。
- 單元固定節奏（暖身 → 講解 → 跟著做 → 自己做 → 錯題重做 → 過關）。
- 閒置時的手指提示、首次使用教學、快速連錯就重播提示（防亂猜）。
- 自然科的「預測 → 觀察 → 解釋」範本。
- 間隔複習、跨單元錯題本、學習地圖、自訂角色。

研究也建議明確不做：排行榜、對戰、商店、答錯扣分、連續天數壓力、發音評分、登入帳號。

**留到後續階段再決定的**

- 英文從哪個年級開始。課綱規定小三，但許多縣市從小一開始教。
- 小一、小二的自然科學要不要做。課綱中自然科學從小三開始，低年級是「生活課程」。
- 儲存庫的授權條款。
